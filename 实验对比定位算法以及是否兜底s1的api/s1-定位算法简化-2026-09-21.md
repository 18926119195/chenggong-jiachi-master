# s1 定位算法简化（2026-09-21）

## 变更内容

### 1. 定位范围收窄（`locateNounInChunkText`）
**改前**：
- 先在 `[truncStart - 50, truncEnd + 50)` 扩展窗口内搜索
- 找不到则退化成整个 chunk 全文搜索
- 置信度分三级：`high`（原始截断内）、`medium`（扩展窗口内）、`low`（chunk 全文）

**改后**：
- **仅在 `[truncStart, truncEnd)` 原始截断区间内搜索**
- 不做 ±50 字符扩窗
- 不做全 chunk 兜底搜索
- **所有匹配位置统一标记为 `confidence: 'high'`**

**理由**：
1. LLM 提取的名词本就来自这个截断文本，扩窗和全文搜索容易误匹配到 chunk 其他位置的同名词
2. 截断边界已经是 LLM 的上下文范围，无需再扩展
3. 简化逻辑，消除误配风险

### 2. 移除最多 5 次匹配限制
**改前**：每个名词最多保留 5 个位置

**改后**：保留所有在截断内找到的位置（实际上截断文本短，单词重复出现次数有限）

**理由**：截断文本短（几十到几百字符），即使不限次数，单词重复次数也不会爆炸；限制 5 次是为全文搜索设计的防御，现在搜索范围已收窄到截断内，此限制无意义。

### 3. LLM 参数调整
**改前**：`temperature: 0.1`

**改后**：`temperature: 0`（完全确定性输出）

**不变**：`thinking: { type: 'disabled' }`（从一开始就是禁用的，在 `src/core/llmClient.js` 中硬编码）

## 影响范围
- **修改文件**：`s1-llm-fill.js`
- **其他脚本**：无依赖（`locateNounInChunkText` 是 s1 私有函数）
- **输出格式**：不变（仍是 `s1-nouns-with-offsets.json`，每个 offset 仍有 `confidence` 字段，只是现在值恒为 `'high'`）
- **下游脚本**：`merge-s0-s1.js` 等消费者无需改动（它们读 `confidence` 字段但不依赖 `medium`/`low` 值）

## 测试建议
运行完整 s1 流程，检查：
1. 是否仍有虚词污染（停用词表已在前一轮扩充，本次改动不涉及过滤逻辑）
