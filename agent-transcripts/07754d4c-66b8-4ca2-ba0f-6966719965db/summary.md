## 核心议题

探讨评分词如何组建拓扑链以及原文展开送入推理 LLM 的机制，并澄清用户对"邻居词定位方式"的理解偏差。

## 主要结论

### 1. 拓扑链构建流程（实际机制）

代码文件：`recall-nouns-llm.js:138-175`

**核心逻辑**：
- 从名词索引中获取评分词的所有出现位置（`offsets`）
- 对每个位置：
  - 向前取 60 字符（`start - TOPOLOGY_WINDOW * 12`）
  - 向后取 60 字符（`end + TOPOLOGY_WINDOW * 12`）
  - 用正则 `/[\s\n.,;:!?]+/` 分词，过滤单字符词
  - 取前后各 5 个词作为邻居词（`neighbors`）
- 邻居词**不限于名词表**，可以是动词、形容词、虚词等任意词

**原文展开流程**：
1. 高分名词 → 拓扑链 → 提取 `chunkKey`
2. 通过 Set 去重（避免 35.2% 重复率）
3. 召回原文块 → 编号为材料【【N】】
4. 统计每块被多少个高分名词命中
5. 拼接成多路径推理 Prompt

### 2. 用户误解澄清

**用户原本理解**：从名词表中找到评分词位置，然后取名词表中前后各 5 个**名词**的位移量。

**实际机制**：按字符范围切片 → 简单分词 → 取前后 5 个**词**（不限名词）。

### 3. 改进方案讨论

**用户期望方案**：邻居词必须来自名词表（只取已识别的名词）。

**实现要点**：
- 需要构建 `chunkNounIndex = Map<chunkKey, Array<{nounId, surface, start, end}>>`
- 对每个 chunk 内的名词按 `start` 排序
- 用二分查找定位当前评分词，取前后各 5 个名词作为邻居
- 边界处理：如果不足 5 个，只取现有数量（不跨 chunk）

**效果差异**：
- 当前方案：邻居包含任意词类，平均 10 个邻居（前后各 5）
- 新方案：邻居只含名词，数量可能不足（名词密度低的区域）

### 4. 附带科普（Git 与灰色文件）

回答了用户关于文件浏览器中灰色文件的疑问：
